# C1 · Duel flow

Files: server `src/duels.ts` (+ routes in `app.ts`), `test/duels.test.ts`; client `src/duel.ts`, hook in `src/arena.ts` (one `createDuelPanel` call), `api-client.ts`, `style.css`, `e2e/duel.spec.ts`; site `src/pages/duel.astro`.

Flow: result panel (any challenge) has **Challenge a friend**: `POST /duels {seed, ticks}` of the same farm, submits the run as the challenger's entry, copies `<origin>/duel/?id=x-…` (desktop uses tendril.hokora.xyz). Needs sign-in; signed out gets a toast and sign-in. `/duel/?id=` shows challenger, score, mosaic and **Accept the duel** → `/play/?mode=challenge&id=`. After the friend's run the panel shows both scores; signed in it calls accept and embeds `replay.html?e=<theirs>&vs=<mine>&embed=1` (the existing sealing rule lets a duel player who has an entry read the other's replay). Signed out: local score vs the challenger plus a sign-in button, nothing submitted.

New routes (please copy into CONTRACTS.md, Arena section):
```
GET  /duels/:id          -> {id, seed, ticks, par, rulesVersion, createdAt, challenger:{login,displayName,avatarUrl}|null,
                             entry:{entryId, netWorth, parTick, mosaic}|null (challenger's best wealth run),
                             accepted, viewer:{isChallenger, accepted, entryId}|null}      404 for non-duels
POST /duels/:id/accept   {} (session) -> {accepted:true, changed, challenger:{login,displayName}}
                             409 until you have an entry on this duel, 422 own duel. Idempotent. Both players follow each other
                             (skipped silently if a follow list is full).
GET  /stats/duels        -> {created, accepted}
```
Storage: `duel_accepts(challenge_id, user_id, created_at)` created lazily (like share_hits), no migration number used. Created = rows in challenges with kind duel; accepted = rows in duel_accepts.

Bug fixed on the way: duel ids are `x-` + base64url, so can contain `_`, but the client `CHALLENGE_ID` and the Electron navigation guard only allowed `[A-Za-z0-9-]` (about 12% of duels would not open). Both now allow `_`; navigation test has a case.
