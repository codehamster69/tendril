# C4: Replay clip export

Files: `packages/client/src/clip.ts` (new), `src/replay-main.ts` (button wiring), `replay.html` (button + status), `e2e/replay.spec.ts` (new test).

Use: "Export clip" in the replay viewer (single run or race, also in `embed=1`). It pauses playback, then records a 1280x720 canvas for 10 s
via `MediaRecorder`: 9 s time-lapse of the whole run (tick = total * elapsed/9 s) and 1 s hold on the final frame. A caption bar shows
"Daily #N · player(s) · net worth" and the site host; a thin line shows progress. Downloads `tendril-<challengeId>-<entryId>.webm` (or `.mp4` where
the browser records mp4). Playback position is restored afterwards. No new dependencies.

Decisions: output length is wall-clock (10 s) so the file always lands in 8-12 s regardless of device speed; frames are drawn from the FarmView
WebGL canvases inside a rAF callback that runs after FarmView's own render (registered first), so no `preserveDrawingBuffer` change in farm-view.
Browsers without `MediaRecorder` or `canvas.captureStream` (older Safari) show "Clip export is not supported in this browser. Try Chrome, Edge or Firefox."

Not done: GIF option (plan said optional, only if under 8 MB). Needs an encoder; left as a follow-up. Firefox not run here (only Chromium installed).
MediaRecorder files carry no duration; some players show 0:00 until played. Fine for posting; remux later if it matters.

Checks: `tsc --noEmit` clean; `playwright test replay.spec.ts` 5 passed (chromium via executablePath override). The new test downloads the file,
loads it in a <video>, asserts 8-12 s duration and that a mid-clip frame is not blank.
Blockers: none.
