# K4 Ratings on final scores (2026-11-17)
- `packages/server/migrations/010_brief_scores.sql`: entries.score, final_score, final_par_tick, hidden_done (NOT NULL DEFAULT 0).
- `ratings.ts`: `standingsView` maps a brief row to (net_worth = final_score, par_tick = final_par_tick; both empty until hidden_done), so
  `buildStandings`, ghosts and tie keys stay unchanged. `buildStandings` skips entries without `source_verified`; ghosts get only verified entries.
- `hiddenChecksDone` gates `rateDue` (before the lock) and `recomputeRatings` (stops the batch like an unsettled contest). 48 h cap = `HIDDEN_WAIT_MS`.
- Recompute of a contest that was rated by the 48 h cap is byte-identical only while its late entries stay unfinished.
- Ratings already stored with ALGO_VERSION 1 make `rateDue` answer `stale-algo` until `ratings:recompute` runs. No rating_contests rows exist before the first 8-player field, so a fresh deploy needs nothing.
- Fixtures: test helpers now insert `source_verified = 1` by default.
