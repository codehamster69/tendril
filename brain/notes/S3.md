## Contract notes
- All contract routes implemented. Extra behaviour: dev login also sets the session cookie; `return` that is not a same-origin relative path gets 400 (not silently defaulted; default is /play/).
- Desktop handoff stores no token: callback marks the nonce hash `ready` for the user, the single successful poll deletes the row and mints a fresh session (tokens never in DB, even encrypted). Nonce = 32..128 chars [A-Za-z0-9_-]. Poll: 200 once, 202 pending, 404 unknown/used/expired.
- CORS: same-origin (request origin or PUBLIC_ORIGIN) only; `app://tendril` gets Bearer-only CORS (cookies ignored, no credentials). Loopback origins (any port) are trusted only when dev auth is enabled (Vite proxy in dev).
- Cookie-authenticated POSTs need `X-Tendril-Client: 1` (403 otherwise), including logout and daily submit. Bearer wins over cookie; a bad Bearer never falls back to the cookie.
- Rate limits: table submission_attempts with kind chunk (10 rolling hour) / daily (20 per UTC day); rejected attempts count, reserved atomically before the body is read.
- Daily: seed = sim `dailySeed(date)` (FNV-1a 32-bit of "tendril-daily:YYYY-MM-DD", 0 -> 1); world `createWorld({id:'daily-<date>', seed})`; only today/yesterday UTC (else 422); rulesVersion mismatch 409; best kept, ties broken by earlier achievement then user id.
- Chunk CAS: `UPDATE farms ... WHERE id=? AND user_id=? AND tick=fromTick`; 0 rows -> 409, whole transaction rolled back. Also `farms.user_id` UNIQUE with INSERT OR IGNORE for concurrent creation.
- Local (`:memory:`/`file:`) mode serialises all operations on one connection, because libSQL's `transaction()` would move an in-memory DB off the connection. Remote URLs use real libSQL write transactions. Do not call `db.query` inside a `transaction` callback (use the `tx` argument).
- GET /api/leaderboard growth board scans all ranked farms (correlated subqueries on worth_history). Fine for launch scale; revisit with a materialised column if it grows.

## Old review findings (S-review.md)
All three preserved: zero-span chunk -> 422; replay paged in SQL (limit 1..2, fromTick cursor, nextFromTick); oversized unfinished uploads get JSON 413 with `Connection: close` flushed before the socket is destroyed (dev.ts), tested natively. Not preserved because they no longer apply: Postgres RLS/roles (replaced by handler ownership checks, tested), PGlite row locks (replaced by CAS plus transactions), local-only display-name auth as default (now dev-only gated by TENDRIL_DEV_AUTH and VERCEL_ENV).
Test change: replay reconstruction now asserts hashWorld equality instead of serialize() text equality (text can differ when weather segments are generated lazily; found as an intermittent failure with random seeds). The hash is the contract.
