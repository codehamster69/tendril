# F5: hands-off updates and releases

## Changed files
- `.github/dependabot.yml` (new): npm (whole workspace) and GitHub Actions, weekly Monday 05:00 UTC; patch+minor grouped into one pull request; Electron majors ignored.
- `.github/workflows/ci.yml` (new): the gate. `gate` = lint, typecheck, `pnpm test` (includes golden replays in sim and lang), assets copy, build. `e2e` = Playwright, no retries. `auto-merge` runs only for `dependabot[bot]` after both pass.
- `.github/workflows/monthly-release.yml` (new): 1st of month 06:30 UTC. If `packages/client`, `sim`, `lang`, `assets/export` or the lockfile changed since the last `v*` tag, bump patch, commit "Release vX" to main, tag, then call `release.yml` with `publish: true`. Manual run defaults to `dry_run`: reports and builds installers, no commit/tag/release.
- `.github/workflows/release.yml`: gained `workflow_call` (inputs `tag`, `publish`); checkout, version check and publish use `inputs.tag || github.ref_name`. Behaviour for a pushed tag and for manual runs is unchanged.
- `brain/DECISIONS.md`: D-028.

## Auto-merge rules (all must hold)
Patch or minor update type; not electron/electron-builder/electron-updater; no changed file under `packages/sim/` or `packages/lang/`; only `package.json`, `pnpm-lock.yaml` or workflow files changed. Otherwise the PR gets label `needs-human` (create the label once, or the step ignores the failure).

## Not verified here
Workflows cannot run in the cloud container. YAML parses; behaviour is untested until it runs on GitHub.
- Repo setting needed: Settings, Actions, General: "Allow GitHub Actions to create and approve pull requests" is NOT needed, but workflow permissions must allow the job-level `contents: write` and `pull-requests: write` (they are set per job). If squash merge is disabled in repo settings, enable it.
- If the `main` branch rule requires pull requests for all pushes, the monthly bot commit is refused. Do not add such a rule without letting `github-actions[bot]` bypass it.
- The Playwright suite has been flaky (F4 is waiting on that). A flaky e2e failure stalls an update; it never merges a bad one. Re-run the failed job.
- First real check: when Dependabot opens its first PR, confirm `auto-merge` ran. Then run Monthly release by hand once (dry run) and look for four installer artifacts.
- GitHub pauses scheduled workflows after 60 days without repository activity; merged updates and monthly releases are the activity that keeps `daily-post.yml` and this schedule alive.
