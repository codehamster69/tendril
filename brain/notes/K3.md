# K3 Server: briefs (2026-11-17)

Code: `packages/server/src/brief.ts` (seeds, par, closing pass, lazy runner), `arena.ts` (rows, par, replay, API fields), verify in `packages/lang/src/verify.ts` (`farmSeed`, `par` in; `score`, `parTick` out). Tests: `packages/server/test/briefs.test.ts`.

## Behaviour
- Setup version comes from `setupVersionFor(date)` unless a test pins `setupVersion`; it is stored on the row, so later requests and replays dispatch by the stored value. With `BRIEF_EPOCH` off nothing changes (old seeds, no hidden farms, `brief: null`).
- Info adds `brief`, `hiddenFarms`, `siblingSeeds` (null until the challenge has closed). Board rows and entry summaries add `score`, `finalScore`, `finalParTick`, `provisional`; submit adds `score`.
- Closing pass: runs from `closer.tick` (once a minute per instance, forced on challenge/board/ratings GETs and the cron). A challenge with nothing left gets an `arena_meta` marker `brief_done:<id>` (one read per later request).
- Verify outage: the entry stays `hidden_done = 0` and is retried; ratings wait up to 48 h (K4). A hidden-farm failure (compile, timeout, illegal log) scores 0 on that farm.
- Duels copy a brief daily: same setup version, par and length (another length is refused), no hidden farms, `siblingSeeds` stays null.

## Cost estimate (free tiers)
Per verified entry, one closing check = 2 verify runs on a daily (4 on a season), about 1-2 s each. A player keeps at most 3 entries per challenge (best per medal), so worst case 6 runs per daily player. 200 daily players: at most 1,200 runs, about 0.5 function-hour a day of verify time, parallel inside a request. Typical (1 verified entry per player): 400 runs. Par setup: 3 runs per daily, 5 per season, once. Turso writes: per entry 1 UPDATE, per pass 2 lock writes plus one marker row per challenge: a 200-player daily costs about 210 writes once, far under the 10M monthly budget. Reads: pending scan is 10 challenge rows + one marker lookup per row at most once a minute; no scans of `entries` except `LIMIT 1` / `LIMIT 3` on `(challenge_id)`.
Vercel verify time is the binding limit: if a daily passes about 2,000 verified players, move the pass to a cron-driven queue.
