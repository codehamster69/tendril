## How it works
- After the humans of a discipline are rated, each model (entries with `author_kind='model'` and a name that reached par; Brevity also needs tokens) is rated in its OWN `rateContest` call: the human standings (with the ratings they started the contest on) plus one ghost slotted in by the board order, sharing a place on an equal tie key. Only the ghost's row is kept. Human results are computed before and never see a model, so they are identical by construction (test compares profile and contest rows byte for byte, also after recompute).
- Skipped when the human field was unrated. Models skip the 14-day GitHub rule and duplicate checks (no github date; model lane is declared). Best entry per model per discipline. Same weights/caps as humans.
- Storage: `arena_meta` key `model_rating:<trimmed lowercased name>`, JSON `{v,name,d:{overall|speed|brevity:{r,n,pk,h[]}}}` (no migration). Written in the contest transaction, so recompute (which deletes the keys) rebuilds them with the humans. Name casing: first-seen display name.
- Cost: one engine run over the field per model per discipline, at most 20 models per contest (name order; extra models are skipped for that contest). One meta write per model.

## GET /ratings/models (for R6 ghost rows)
`{models:[GhostModel]}`, best overall rating first. A model is listed with >= 3 overall rated days and a rated run in the last 30 days.
`GhostModel = {name, rating, tier:{key,name,floor,next}, provisional (events<5), events, peak, lastRatedAt, humanRank, humans, percentile, disciplines:{overall|speed|brevity: null | same fields}, history:[{challengeId,kind,closesAt,place,field,performance,delta,before,rating,entryId}] (overall, latest 30)}`.
`humanRank` = 1 + established active humans with a strictly higher rating in that discipline; `humans` = ladder size. To interleave a ghost row on the leaderboard: show it just before human rank `humanRank` (e.g. after the row ranked humanRank-1), styled as a ghost, not numbered. R6 can fetch `/ratings/models` once and filter by `disciplines[d]` for the speed/brevity tabs (null = none).

## Caveats
- A ghost is counted in its own engine call's zero-sum, so its delta can be nudged 1-2 points versus a lone computation. Accepted.
- Model identity is the typed name: anyone can submit under any name and move that model's rating. Docs say declarations are not verified. Day-one models only appear after 3 rated days; humans needing 14-day accounts is not applied to models.
- Models are rated only in contests rated after this ships (existing history needs a `ratings:recompute`).
- `humans: 0` and percentile 100 when the ladder is empty (placement week).
