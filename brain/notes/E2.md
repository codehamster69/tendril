# E2: streamer room race

Rules version stays 3, goldens untouched, no server change, no migration, no new route.

## What it is
`/play/room.html?id=<duel id>` shows up to 16 runs of one duel on a single clock, ranked live by net worth. The host's
farm (the duel challenger's best run) is drawn large; everyone else is a small farm tile that moves to its live rank.
The duel page (`packages/site/src/pages/duel.astro`) has a "Watch everyone race" link, shown once the duel has a posted score.

## Files
- `packages/client/room.html`, `src/room-main.ts`: page, DOM and frame loop. Added to the Vite inputs in `vite.config.ts`.
- `src/room.ts`: `loadRoom` (fetch duel, board, replays; one `Timeline` per run from `replay-view.ts`) and `drawMiniFarm`.
- `src/room-core.ts`: pure logic with no DOM or sim imports: `pickPlayers`, `rankOrder`, `RoomClock`, types. Node can test it.
- `src/room.test.ts` (added to the client `test` script), `e2e/room.spec.ts` (4 tests; a 5th, a screenshot, runs only with `SHOT=<png>`).
- `packages/site/src/pages/duel.astro`: the link.

## Data and sealing
No new endpoint. Players come from `GET /duels/:id` (host = `entry`) and `GET /challenges/:id/board?medal=wealth&limit=16`;
each replay from `GET /entries/:id/replay`. The host always keeps a seat (it replaces the 16th if beaten by 16 others).
A 403 (sealed) run is never played: it gets a "Sealed" tile, stays out of the ranking, and a note says to finish your own
run to unlock. A run with no stored log shows "No replay stored". So a visitor with no entry on the duel sees sealed tiles;
a player with an entry (or the owner) sees everything the sealing rules allow.

## Decisions
- **Small farms are 2D canvases, not FarmView.** One WebGL context per farm hits the browser limit (about 16) and software
  GL manages a few fps. `drawMiniFarm` draws one square per tile (soil, crop colour by stage, buildings, bots).
- **The large host farm is flat 2D by default too**, with a "3D host" checkbox (or `?view=3d`) that swaps in the real
  `FarmView`. Reason: FarmView under swiftshader (CI, no GPU) took about 150 ms a frame, so the 30 fps requirement could not be
  met with it on by default. Streamers with a GPU can switch it on. Flip the default if Rohan prefers 3D.
- Frame loop draws at most 30 times a second on any screen (`RoomClock.due`); the clock is 10 ticks/s at 1x (default 4x).
- Timelines are built one at a time with a yield between, because each re-runs its whole log once.
