# R8: Rating in the terminal (`tendril me`)

## Changed files
- `packages/lang/src/arena-cli.ts`: new `me()` after `login()`, with a small section of types. It sits here because `api()`, `loadToken()` and `fail()` are private to this module, the same as `login`/`submit`.
- `packages/lang/src/cli.ts`: `me` dispatch and the usage string (import and two lines only).
- New `packages/lang/test/cli-me.test.ts` (3 tests, same harness as `cli-arena.test.ts`: in-memory server from the migrations, dev login, `execFile` of `src/cli.ts`).
- `packages/site/src/pages/docs/cli.mdx`: one line in the command block.
- No changes to the server, CONTRACTS.md, or root manifests.

## Behaviour
- Requests: `GET /me` (Bearer; gives the login, so `TENDRIL_TOKEN` works without `auth.json`), `GET /players/:login` (streak and the three ratings), `GET /ratings/me/latest` (Bearer; last rated contest). The last two run in parallel.
- Output: display name and login; one line per discipline (`1320  <tier> (next at N), rank R`, `In placement, n of 5`, or `unrated`); a "Last rated" block for the newest contest with place, field, rating and delta per discipline, plus `promoted to <tier>`; a streak line (`none` at 0, singular/plural otherwise, with best).
- Signed out (no token) throws `Not signed in. Run: tendril login`, the same as `submit`, so exit code 1 and the message on stderr. An expired or unknown token gets `Your sign-in has expired. Run: tendril login`.
- Placement length 5 is a constant in the CLI, mirroring `PLACEMENT_EVENTS` in `packages/server/src/ratings.ts`. If the server value changes, this must change too.

## Decisions
- Used the existing `/me` route for the login rather than storing the login in `auth.json`, so a stale saved login can't show someone else's ratings after a `TENDRIL_TOKEN` switch.
- Friendly text for an unrated player with no rating anywhere; each discipline shows `unrated` separately.
- Did not print percentile (its exact meaning is server-side; rank only).
