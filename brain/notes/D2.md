## Checked and holding (tests in arena-attack.test.ts unless noted)

- **Accept**: needs a session, a run of your own, not your own duel, not a daily, idempotent; 401/409/422/404 tested. CSRF header and origin tested on every mutating route.
- **Sealed replays and programs**: all paths go through `replayVisible`; `/entries/:id`, `/replay`, `/source`, `/sources`, `/r/`, `/og/` expose no log or program (share cards show the mosaic and score only). Edge caching applies only to anonymous 200s, which exist only once settled.
- **Resubmitting another player's log**: identical logs share a rank group; a trivially changed copy is only possible where the replay is readable (F1, F10).
- **Bodies**: 2 MB body cap, 20,000 actions, 32 KB source, strict key sets, content type, UTF-8 (ATTACK1 plus existing arena tests).
- **Verify**: secret header with timing-safe compare, 64 KB body, 8 s deadline checked every 4 ticks, string-literal token charge, deep nesting returns a compile error (test), memory bounded (F2).
- **Budget guard**: read-only refuses every arena write with 503 and keeps reads; tight mode quarters the allowances (tests). Fails closed if the guard cannot read the database.

## Cost per submission (measured, in-memory libSQL, new entry on an open daily)

11 read statements and 4 write statements (attempt cleanup, attempt row, entry, player counter), which is 3 rows written, as `WRITES_PER_ENTRY` assumes. A repeat of your own log is now 1 read and 1 write (the attempt) before the 409. With a program, add one verify call. Read rows grow with rank, not board size, apart from F9.
