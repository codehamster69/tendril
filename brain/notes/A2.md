## Decisions
- Routes: every `/challenges`, `/entries`, `/duels` route in the contract except `/source`. `/players`, `/follows`, `/badge`, `/og` belong to B5/B4; only the `follows` table is here.
- Lazy creation only for today/yesterday (daily) and this/last week (season), so a request cannot fill the table. Before 2026-12-01 daily numbers are <= 0.
- Entries are stored per medal (best wealth, fastest par, shortest tokens), max three, ties to the earlier entry. A run that improves nothing is not stored; the response says `improved: false`.
- Copied log: unique index on (challenge, log_hash) for non-empty logs. Same player resubmitting the same log is a 200 repeat. Empty logs are exempt (they carry no information). Note honest players using the same bundled program on the same seed produce identical logs and the second gets 409; flagged for D2/the plan owner.
- Legacy move: `daily_entries` rows are copied into challenges/entries by `moveLegacyDaily` at start-up (SQL cannot compute the FNV seed), guarded by `arena_meta`. The old table is kept as an archive and no longer written.
- Old `/api/daily*` routes go through the same pipeline, so they get the copied-log rule. They keep "yesterday still accepted" (`LEGACY_GRACE_MS` = 1 day) because the existing tests and desktop 0.1.x need it. Risk: a late legacy entry can be made after a replay is unsealed. Set the constant to 0 when 0.1.x is gone; D2 should review.
- `source`/`sourcePublic` are validated but not stored; `tokens` is always null (C3).
- Percentile = floor(100 * (total - rank + 1) / total).
- Rate limits: 60 entries and 20 duels per user per UTC day (new `entry`/`duel` kinds in `submission_attempts`); the old daily limit of 20 is unchanged.
- Added beyond the contract (additive): `total` on submit; `userId`, `mosaic`, `authorKind`, `model`, `createdAt` on board rows; `rulesVersion` on replay; `sealed` on the entry summary.
- `entriesPerDay` counts stored entries by creation day (pruned entries are not counted), last 30 days.
