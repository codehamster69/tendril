## Decisions
- **Expansion, not a new engine.** The parser reads `tend`, `when` into private node shapes; `desugar` replaces them before `compile` returns. Neither engine learned a new node. Generated nodes carry the position of the line that produced them (debugger and line heat point at the player's `tend` line) and skip the lesson feature check.
- **Fixed order per tile:** walk, scan, first matching rule, first matching between-tile rule, auto-drop if the bag is still full. After the last tile: go to the nearest drop, deposit, between-tile rules once more, `wait 10` if the pass took no ticks. Documented in LANGUAGE.md 11 so each tick is explainable.
- **Top-level `tend` repeats forever** from the first `tend` down; above it runs once. Inside your own loop, you control it.
- **Between-tile rules (top-level `when`) are first match wins**, same as tile rules (one rule to learn). `when full: sell everything` works because auto-drop runs after the rules.
- **`sell everything`/`sell X` and `plant X` are rule-only verbs** (walk to drop and deposit then sell; till first if needed). Two-argument `sell` and calls inside functions stay literal.
- **`else clover` reuses the verb** (`plant carrot unless tired, else clover`); `else water` (a full action) also works.
- **Bots:** contiguous share `L*k/n .. L*(k+1)/n` of the tile list (integer maths), so one program runs every bot with no overlap; recomputed each pass.
- **Brevity (item 3):** `countTokens` is untouched: it counts what the player wrote (`tend`/`when` count as words), never the generated code. starter-tend is 60 tokens against 128 for starter.sprout. Old programs and pars score as before.
- **Keywords are contextual.** `tend`, `when`, `every`, `unless`, `region` are in KEYWORDS (highlight, reference) but the parser only treats them as special at a block head (`tend ...:`) or rule line (colon outside brackets), so variables or functions with those names still work (tested).
- **Warnings:** `compile` now returns the program when there are only warnings (it used to null it on any diagnostic; no program produced one before). Warning cases: contradictory conditions (`ripe and empty`), a rule an earlier one always catches (DNF check; `dry` equals `moisture < 25`).
- **Unknown condition word** suggests from the plain words first (`dryy` suggests `dry`), then ordinary names.
