# R3: Portfolio page

## Changed files
- `packages/site/src/pages/u.astro` (thin page), new `packages/site/src/components/Portfolio.astro` (markup + `.pf-*` styles, tier tokens), new `packages/site/src/scripts/portfolio.ts` (render logic).
- Reads `GET /players/:login` (R2 `rating`), `GET /entries/:id/source` for pinned programs. Follow button kept.

## Decisions
- Layout follows the mockup: identity band, facts, history chart (SVG, tier bands, Overall/Speed/Brevity switch, every dot a link to `/r/<entryId>`), disciplines, rated results (switch also drives the table; Overall also lists recent below-par/awaiting entries), medals, 20-week garden, ladder with distance to next tier, signature farms (top 3 recent mosaics by net worth).
- States: rated; placement ("1,264?", "In placement, 3 of 5", no title, ladder row not highlighted); no rated runs ("Unrated" with explanation); unknown login / no login (message, no profile).
- Light-theme tier colours are darker than the mockup: its seedling, shoot, vine and grove failed 4.5:1 as text on paper/panel/10% band. New light values: seedling #696120, shoot #3d6a20, vine #1b6b5e, orchard #af3028, grove #904f0c; dark orchard #e6736a. All 8 tiers >=4.5:1 on paper, panel and band in both themes (computed). Tokens are `--tier-*` scoped to `.pf`; R6 may want to promote them to global.css.
- Title, meta description, og:title/description, canonical are set at view time (the site is static, one `/u/` page). Crawlers that do not run JS see the generic title. Real per-player SSR needs a server/edge route (R5's `/og/u/` image is the other half); request for coordinator.
- Garden has only `rated history` + the 10 `recent` entries to draw from; older below-par days are not shown. A `days` field on the player API would fix it.

## Gap: pinning (needs server work)
No pin API or `pinned` field exists. UI reads `pinned: (entryId | {entryId})[]` and shows each program via `/entries/:id/source` (published, verified programs only). The owner sees Pin/Unpin on result rows only when the response contains `pinned`, and it PUTs `/api/players/me/pinned {entryIds:[<=3]}` (proposed, nonexistent). Server must: store up to 3 entry ids per user, validate ownership, add `pinned` to `/players/:login`, and add the PUT route. Until then the section is hidden.
Also not shown: duel win/loss and join date (no data in API).
